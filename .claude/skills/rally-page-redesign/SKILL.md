# Rally 페이지 디자인 개편

## 언제 사용

- 사용자가 `docs/design/`에 새 시안 HTML을 넣고 "이대로 적용해줘"
- 사용자가 "OO 페이지 디자인 클로드에게 줄 프롬프트 줘"
- 아직 zinc인 페이지 본문을 `--rally-*` 토큰으로 바꿀 때 (요청받은 페이지만 — 알아서 퍼뜨리지 않음)

## 먼저 읽을 것

1. `docs/design/references.md` — **"시안 대비 구현 변경점"이 실제 기준**. 시안과 다르게 정한 것(버튼 배치·문구·숫자 정의)이 여기 있음. skill에 복사하지 말고 매번 읽기
2. 해당 시안 라이트 + `-dark` 둘 다 (인라인 style — 레이아웃·색·타이포만 참고, 마크업 그대로 옮기지 않음)
3. 바꿀 컴포넌트 전부 + 같은 데이터를 쓰는 다른 화면(예: 캘린더 ↔ '오늘' 다가오는 일정)

## 작업 순서

1. 브랜치 `feat/<page>-redesign` (develop에서)
2. **plan mode로 바꿀 파일 목록 + 파일별 변경 요약을 보여주고 승인** (CLAUDE.md 1번). 계획에 "그대로인 것"(API·URL 파라미터·모바일) 명시
3. 구현 — 데스크톱(md+)만. 데이터·URL 로직은 건드리지 않음. 모바일 바텀시트·카드는 동작 유지, 색만 토큰으로 따라오는 건 허용(사용자에게 알림)
4. `pnpm --filter web typecheck` · `lint` · `build`
5. 개발 서버에서 사용자에게 라이트·다크 + 엣지(빈 상태·넘침·깜빡임) 확인 요청. 사용자가 고친 문구·배치는 바로 반영
6. `references.md`: 시안 표에 파일 추가 + "시안 대비 구현 변경점"에 페이지 섹션. `docs/todo.md` 디자인 항목 갱신
7. 커밋·PR (요청 시). 머지는 `gh pr checks` 전부 통과 확인 후

## 토큰 대응 (시안 hex → Tailwind 클래스)

새 토큰은 기존 걸로 안 될 때만. 만들면 `:root` + `.dark` + `@theme inline`의 `--color-*` 세 곳 모두.

| 시안 라이트 | 클래스 | 용도 |
|--|--|--|
| #F6F7F5 | `bg-paper` | 페이지 바탕 |
| #FFFFFF | `bg-surface` | 카드·패널·칸 |
| #D9DCD8 | `border-line` | 카드 바깥 테두리 |
| #E7E9E6 | `border-divider` / `bg-divider` | 카드 안 행 구분, 1px 격자 선 |
| #FAFBF9 | `bg-thead` | 표·요일 머리 |
| #1C1F1D / #3F4441 / #4F5450 / #7A7E78 | `text-ink` / `-ink-soft` / `-ink-muted` / `-ink-faint` | 본문 / 요약 / 보조 / placeholder |
| #8E928D | `text-icon-faint` | 빈 칸 아이콘, 다른 달 날짜 |
| #1F3D30 | `text-heading`, `bg-primary`, `bg-button` | 섹션 제목, 진행바·체크, 채운 버튼 |
| #BFC4BE | `border-btn-border` (+ `text-btn-fg`, `bg-btn-bg`) | 테두리 버튼·입력 |
| #E6EEE8 + #1F3D30 | `bg-chip-on-bg` + `chip-on-border` | 선택 상태(칩·선택한 날) |
| #F2F4F1 | `bg-row-hover` | 행 hover |
| #A33B20 / #9A6700 | `text-alert` / `text-warn` | 마감 오늘·내일 / D-2~3, 변경사항 있음 |
| #E9B949 | `bg-marigold` | 포인트만: 로고·챌린지 바·**목표를 다 채운 막대**(평소 `bg-primary`, 100%면 `bg-marigold`). 비교용 막대는 100%여도 primary. 적용 현황·남은 곳은 references.md '색' |
| 일정 유형 | `components/calendar/event-tone.ts` `EVENT_TONE` | 마감·시험·면접·발표·기타 점+글자 |
| 지원 상태 | `bg-st-*` | 채용 상태 점 |

다크 값이 시안과 토큰이 다르면 시안 다크 HTML을 기준으로 확인 (예: 오늘 원은 다크에서 `bg-button` #2F5A47이지 `primary`가 아님).

## 재사용 코드

- 페이지 래퍼 (채용·캘린더와 동일):
  `min-h-screen bg-paper font-plex text-[15px] leading-normal text-ink tabular-nums` > `mx-auto flex max-w-310 flex-col gap-5 px-4 pt-6 pb-16 md:px-10 md:pt-9`. `loading.tsx` 스켈레톤도 같은 래퍼
- h1: `text-[26px] leading-tight font-bold tracking-[-0.01em]`
- 섹션 제목: 카드·페이지 섹션 `text-[17px] font-bold text-heading`(today `Card.tsx`, 통계), 사이드 패널 안 소제목 `text-[15px] font-bold text-heading` (+ 개수는 `font-medium text-ink-muted`)
- 진행바: 목록 줄 안 얇은 바 `h-0.75`~`h-1`, 구성 막대·단독 진행바 `h-1.5`
- 흐린 글자: `text-ink-faint`(대비 4.3:1)는 placeholder·취소선 완료 항목·"저장됨"만. 읽어야 하는 보조 글자는 `text-ink-muted`
- 모달(회사 추가·챌린지 만들기)만 ✕ + [취소][추가하기/만들기]. 팝오버·패널엔 [취소] 없음
- `components/jobs/cells/popover-style.ts`: `BUTTON_PRIMARY`(채운) · `BUTTON_SECONDARY`(테두리) · `BUTTON_TEXT`(글자) · `POPOVER_CLOSE`(✕ 40px) · `POPOVER_INPUT(_BASE)` · `POPOVER_CARD`
  - 폭을 따로 줄 입력은 `POPOVER_INPUT_BASE` (w-full과 폭 클래스 충돌)
  - 상수에 이미 있는 패딩을 덮으려 클래스를 덧붙이지 말 것 — 순서상 안 먹을 수 있음
- 깜빡임: 행은 `animate-[row-flash_2.5s_ease-out]`(JobsTable — `?highlight=`), 칸은 `.date-flash`(::after 안쪽 테두리 — 선택 표시와 안 겹침, 부모 `relative` 필요)
- 사이드 패널 구조: 채용 `CompanyDetailPanel` / 캘린더 `CalendarDayPanel` — 제목 줄(18px bold + ✕) → `border-divider` 구분선 섹션(px-5 pt-4 pb-4.5)
- 메모·회고 입력: 캘린더 날짜 패널 메모 섹션 패턴 — 상태 "저장됨"(ink-faint) / "변경사항 있음"(warn 점+글자) `role=status`, 아래 줄 왼쪽 휴지통 [삭제](저장된 값 있을 때만) … 오른쪽 [저장], Ctrl/⌘+Enter(표시 X, `aria-keyshortcuts`)

## 정해진 UI 규칙

- 닫기 = ✕(제목 줄), 삭제 = 휴지통. 입력형 팝오버도 [취소] 없이 ✕ + 아래 [지우기] … [되돌리기(고쳤을 때만)][저장]
- 클릭 영역 최소 40px (`min-h-10`, `h-10 w-10`)
- 주요 내용 = 흰 카드(`border-line rounded-lg bg-surface`), 보조 정보 = 선. 한 줄에 카드와 선을 섞지 않음
- 칸 상태는 표시 위치가 겹치지 않게 (오늘 = 숫자 원, 선택 = 배경+안쪽 테두리, 깜빡임 = 오버레이)
- 정렬된 숫자는 `tabular-nums`, 숫자 옆 %는 오른쪽 끝
- 범례·캡션은 색만으로 구분이 안 되는 것만 (메모 아이콘처럼 모양으로 알 수 있으면 뺌)
- 접근성: 칸 버튼은 `aria-pressed` + 읽히는 `aria-label`("11월 5일, 오늘, 일정 2건, 메모 있음")

## 문구 규칙

**기준: 처음 보는 사람이 한 번 읽고 뜻을 알고, 뭘 하면 되는지 아는 문구.** 쓰고 나서 화면에서 소리 내 읽어보고 어색하면 고친다. 애매하면 후보 2~3개를 사용자에게 보여주고 고르게 한다(채용·통계 개편 때 문구 대부분이 이렇게 정해짐).

읽기 쉽게
- 한 문장에 한 가지. 짧게 — 같은 뜻이면 더 짧은 쪽("말이 길다"는 지적이 반복됨)
- 개발·내부 용어 X: sync, 데이터, 항목, 처리, 레코드, 상태값 코드. 사용자가 화면에서 보는 이름으로
- 같은 것은 앱 전체에서 같은 단어 — 리스트의 지원상태 이름 = 통계 막대 라벨 = 필터 이름. 새 이름을 만들지 않음
- 정해진 이름(화면 문구 기준): **루틴**(블록·시간블록·라벨 X) · **회사**(기업 X) · **포트폴리오**(포폴 X) · **아직 안 한 루틴**(미체크 X) · 학습 표시는 버튼 이름 그대로 '이해완료'·'복습필요' · 띄어쓰기 "이번 주"·"사용 중"
- 말투는 해요체로 통일("~했습니다"·"~입니다" X). 오류는 "추가하지 못했어요. 잠시 후 다시 해보세요."처럼 다음 행동까지. 서버 오류 원문(err.message)·추측("중복일 수 있음")을 화면에 그대로 내보내지 않음
- 사용자가 내부 값(영문 key 등)을 직접 정하게 하지 않음 — 필요하면 코드가 만듦
- 헷갈리는 단어는 뜻이 하나로 읽히는 말로("지남" → "마감됨", "면접 중" → "면접 단계" + 툴팁으로 포함 범위)
- 숫자는 단위와 같이("2곳 중 2곳 통과"), 분모가 뭔지 문장에 드러나게("결과 나온 5곳 중")
- 라벨의 뜻 = 실제로 세는 기준. 라벨만 보고 오해할 수 있으면 라벨을 바꾸지 기준을 바꾸지 않음

행동이 보이게
- 사용자 말투(해요체), 행동 유도("다시 학습해보세요", "채용 리스트에서 일정 추가하기 ›")
- 버튼은 누르면 일어나는 일을 동사로: "저장", "만들기", "일정 추가하기". "확인"·"OK"·"제출" X
- 빈 상태 = 무엇이 없는지 + 다음 행동 한 줄("아직 만든 루틴이 없어요. 아래에서 하나 추가해보세요.")
- 되돌릴 수 없는 동작은 확인 문구에 결과를 씀("되돌릴 수 없어요", 포기는 "기록은 남아요")
- 오류 = 무엇이 안 됐는지 + 어떻게 하면 되는지. 사용자 탓 X("제목을 입력하세요" 정도로 짧게)

빼는 것
- 기능·작동 원리 설명("오래된 순으로 모아봅니다"), "~하려면 ~에서 해주세요" 안내문, 화면만 봐도 아는 사족 캡션("오늘 페이지에도 같이 보여요"는 사용자가 뺌). 정말 필요한 설명은 툴팁으로
- 단위: 기준 문구 "개 회사", 큰 숫자·그 안의 개수 "곳", 마감·일정·공고 "건", 목록 개수 "개"
- 날짜: 마감은 "D-2" + "10.26 월 23:59", 지난 건 "마감됨", 빈 칸 "—"
- 지표는 엄격하게: '완료'는 전부 끝난 것만, 분모는 결과가 나온 것만. 숫자를 후하게 만들려고 정의를 완화하지 않음
- 시안에 있어도 데이터로 셀 수 없는 숫자(추정치)·상대 날짜("이틀 뒤") 등은 사용자와 확인 후 뺌

## 시안 요청 프롬프트 틀

디자인 세션 Claude는 저장소를 못 봄 → `docs/design/skill/rally-design/SKILL.md`를 그쪽 skill로 쓰고, 프롬프트에는 페이지 고유 내용만:

1. 결과물: `rally-<page>.html` + `-dark.html`, 데스크톱만
2. 기준: 첨부(`rally-dashboard.html`, 비슷한 기존 시안, `references.md`), 사이드바 활성 메뉴
3. 페이지에 있는 것 — 지금 코드의 섹션·기능·빈 상태 문구·제약(최대 개수 등)을 **실제 코드에서 읽어** 나열. "기능은 유지, 모양만 새로"
4. 정해줬으면 하는 것 — 배치·상태 표현 등 열린 질문 (편집·hover·빈 상태도 한 장에)
5. 샘플 데이터 — 오늘 날짜 기준, 넘침·빈 칸·여러 상태가 다 보이게
6. 범위 밖(통계는 다음에 등) 명시
