# 디자인 레퍼런스

스크린샷은 `./references/`에, 각 항목은 아래 형식으로 추가.

## 시안

디자인 툴에서 뽑은 정적 HTML — 브라우저로 바로 열어 비교. 인라인 style이라 **레이아웃·색·타이포만 참고**하고 마크업을 그대로 옮기지 않는다(토큰은 `globals.css --rally-*`).

| 파일 | 내용 | 구현 |
|--|--|--|
| `rally-dashboard.html` | '오늘' 대시보드 + 사이드바 라이트 | `/today`, `Sidebar.tsx` |
| `rally-dashboard-dark.html` | 같은 화면 다크 | `globals.css` `.dark`의 `--rally-*` |
| `rally-jobs.html` · `rally-jobs-dark.html` | 채용 리스트 '자세히' | `/jobs` `JobsTable`·`JobsFilters` (1단계) |
| `rally-jobs-compact(-dark).html` | 채용 리스트 '간단히' + 사이드 패널 | `JobsTable` 합친 열, `CompanyDetailPanel` |
| `rally-jobs-parts.html` | 회사 추가 모달 · 셀 팝오버 5종 · 빈 상태 2종 (라이트만) | `components/jobs/cells/*`, `AddCompanyButton` |
| `rally-stats(-dark).html` | 기업 통계 | `/jobs/statistics` |
| `rally-calendar(-dark).html` | 캘린더 + 날짜 패널 | `/calendar` `components/calendar/*` |
| `rally-routines(-dark).html` · `rally-routines-parts.html` | 루틴 트래커 · 챌린지 추가 모달 · 빈 상태 2종 | `/routines` `components/routines/*` |
| `rally-routines-stats(-dark).html` · `rally-routines-stats-parts.html` | 루틴 통계 · [월] 선택 · 숫자 0 · 빈 상태 | `/routines/statistics` `components/routines/stats/*` |
| `rally-workouts(-dark).html` · `rally-workouts-parts.html` | 운동 기록 · 세트 상태 · 타이머 · 종목 추가 모달 · 빈 상태 | `/workouts` `components/workouts/*` |

**현재 상태**: 숲색 `#1F3D30` · 메리골드 `#E9B949`(로고·챌린지 포인트, 시안의 황토 `#C8963E`에서 변경) · 바탕 `#F6F7F5`, IBM Plex Sans KR + Noto Serif KR(인사말). 사이드바(전 페이지)와 `/today`에 적용. 다른 페이지 본문은 zinc — 페이지별로 개편할 때 같은 토큰으로 확산. 모바일(BottomNav)은 별도 시안 예정.

### 시안 대비 구현 변경점

적용하면서 시안과 달라진 곳. **새 페이지 시안을 요청할 때 디자인 세션에 이 섹션을 그대로 공유**해서 기준을 맞춘다. 공통 색·컴포넌트·문구 규칙은 디자인 세션 skill `docs/design/skill/rally-design/SKILL.md`(claude.ai에 zip 업로드)에 — 여기엔 페이지별 차이만.

**색**
- 포인트색: 황토 `#C8963E` → 메리골드 `#E9B949` (라이트·다크 공통). 포인트로 아껴 쓰기
- **메리골드 규칙: 로고 깃발 + 챌린지 진행바 + "목표를 다 채운" 막대만.** 목표가 있는 막대는 평소 primary, 100% 채우면 메리골드. 목표가 아닌 비교용 막대(요일별 평균·순위·구성 막대 등)는 100%여도 primary
  - 적용됨: '오늘' 루틴 바(오늘 블록 전부 체크) · '오늘' 운동 바(목표 100%) · 루틴 통계 요약 띠 '완료한 날'(전체 일수)·'평균 달성률'(100%) · 채용 통계 '최종 합격' 조각
  - 예외: 챌린지 진행바는 진행 중에도 항상 메리골드 — 목표를 다 채우면 자동 완료돼 진행 중 목록에서 빠지므로 "다 채움" 조건으론 볼 일이 없고, 챌린지 자체를 알아보는 표시 역할(2026-11-04 확정)
  - 개편 때 적용할 곳: 운동 '부위별 주간 목표'(`MuscleGoalsCard`, 세트 목표 100%). 휴식 타이머 진행 바는 목표가 아니라 대상 아님
- 일반 진행률 바는 숲색 계열(라이트 `#1F3D30` / 다크 `#8FB5A0`), 목표 미달 바 `#7F988A` / 다크 `#5F8873`
- 나머지는 시안 그대로 (숲색 `#1F3D30`, 바탕 `#F6F7F5`, 카드 `#FFFFFF`, 마감 `#A33B20` / 다크 `#E8957A` 등)

**로고**: 원 없이 깃대(`#F4F2EC`) + 메리골드 삼각 깃발

**사이드바 (전 페이지 공통)**
- 메뉴: 오늘 · 캘린더 · 채용 · 루틴 · 운동 · 학습 · 블로그
- 하위 메뉴(접기 가능): 채용(리스트·통계), 루틴(트래커·통계), 운동(기록·통계), 학습(오늘의 학습·복습·통계)
- 메뉴 줄 40px, 하위 메뉴 32px. 넘치면 메뉴 영역만 스크롤(스크롤바 숨김)
- 하단: 왼쪽 `⚙ 설정`(메뉴와 같은 모양), 오른쪽 끝 🌙 테마 · 🔔 알림
- 닉네임 표시 없음. 로그아웃은 설정 페이지에만(이탈 유도 안 함)
- 관리자 계정일 때만 설정 위에 '관리자 페이지' 줄 — 청록 `--rally-admin-side-*`: 평소 배경 #24484A + 1px 테두리 #3B6E6B + 글자 #D2ECEA(일반 메뉴와 구분되는 버튼 모양), hover는 색 그대로 › 가 나타나고 아이콘 2px 이동, 활성 배경 #9FD0CC + 글자 #12302F(다크 값 별도). 관리자 페이지 내부 대표색은 `--rally-admin`(#2E6E6B / #8CC8C2)

**'오늘' 페이지**
- 헤더에 벨·다크모드 버튼 없음 (사이드바로)
- 인사말은 닉네임만 숲색 (다크 `#A9CBB7`)
- 요약 문장: "오늘 마감 N건, 일정 N건이 있고 루틴은 N개 남았어요."
- 학습: '답 보기' 없음 → ‹ › 화살표로 5문제 미리보기 + 채운 버튼 '답 보러 가기'(`/learn?q=`). 기록한 문제는 작게 "이해함으로 기록했어요". 문제 길이가 달라도 섹션 높이 고정
- 채용: "서류 통과율 36% · 결과 나온 N곳 중 M곳" (분모는 결과 나온 곳만)
- 운동: 하단 설명 문구 삭제, 숫자는 "6 / 10세트"
- 블로그 버튼: "전체 보기"
- 오늘의 학습은 흰 카드 (오른쪽 열: 채용 현황·이번 주 운동은 선, 학습만 카드 — 직접 하는 일이라 왼쪽 카드들과 같은 무게)
- 채용 현황: '면접 중' → '면접 단계'(툴팁 "서류합격 · 1차합격 · 2차합격"), 서류 통과율 설명 "2곳 중 2곳 통과"

**채용 리스트** (`/jobs`, 데스크톱만 — 모바일 카드는 그대로)
- 동작·데이터는 그대로: 공고 링크는 [저장] 유지, 제출본은 이력서 1 · 포트폴리오 1 선택(시안의 문서 여러 개 체크 X), 채용 필터는 '채용중' 칩 하나(시안의 '채용 안 함' X)
- 닫기: 입력형 팝오버(마감일·공고 링크·메모)는 [취소][저장], 즉시 저장형(일정·제출본)은 제목 줄 ✕. 추가 모달 ✕ 유지
- 삭제 아이콘은 휴지통(행·일정), 닫기는 ✕
- 라벨: 필터·표 머리글 "채용여부", 즐겨찾기 버튼 "즐겨찾기", 빈 상태 문구에서 '위' 삭제
- 마감일 칸: "D-2 10.26 월 23:59". 진행 중인 회사만 오늘·내일 `alert`, D-2~3 `warn`(호박색 #9A6700 / 다크 #E3B35C) — 끝난 회사(탈락·최종합격·지원취소)는 강조 X. 지난 건 "마감됨", 빈 칸은 "—"(행 hover 때 "+ 추가")
- 마감일 팝오버: 날짜·시간 입력 분리, 시간 비우면 23:59
- 일정 유형 선택은 커스텀 Select(점 아이콘)
- 열 보기 토글 [간단히 | 자세히] (시안 '전체 열' → '자세히'), localStorage `rally.jobs.columns`, 기본 자세히. 새로고침 깜빡임 없게 `app/layout.tsx` 초기화 스크립트가 `<html data-jobs-columns>`를 달고 CSS로 열 선택
- 간단히: 보조 4열 → "공고 · 일정 2 · 문서 2 · 메모"(없으면 "비어 있음") → 누르면 오른쪽 사이드 패널(시안에 없어서 새로 설계). 패널은 팝오버와 같은 Editor 재사용
- 팝오버 버튼 정리(시안과 다름): 닫기는 5종 모두 제목 줄 ✕(입력형 [취소] 제거), 아래 줄은 [지우기] … [되돌리기(고쳤을 때만)][저장]. 지우기는 저장된 값이 있을 때만, 바로 삭제. 공고 링크의 열기·복사는 입력칸 아래 작은 글자 링크(시안의 [비우기]는 [지우기]로)

**기업 통계** (`/jobs/statistics`) — 시안과 숫자 정의가 다름(상태 이력이 없어 추정 없이 셀 수 있는 것만, `lib/jobs-stats.ts` `computeJobsSummary`)
- 지표 위 한 줄: "담아둔 N개 회사 · 채용중 N곳 · 즐겨찾기 N곳"
- 핵심 지표 3열: 지원한 회사 N곳 / 진행 중 N곳(서류 결과 대기 + 면접 단계) / 서류 통과율 %(**서류 결과가 나온 곳 기준**, /today와 같은 계산). 결과 나온 곳 5곳 미만이면 숫자 흐리게 + "표본 적음"
- 큰 숫자 아래 얇은 구성 막대 → 설명(13px 흐리게) → 점선 → 내역. 내역 점 색 = 막대 조각 색(범례). 1열 막대는 끝난 곳 비율(최종 합격 메리골드·탈락·지원취소, 빈 칸 = 진행 중), 2열 서류 결과 대기(st-applied)·면접 단계(st-int1-passed), 3열 서류 통과(primary)·서류 탈락
- 내역(캡션 없음): 최종 합격·탈락·지원취소 │ 서류 결과 대기·면접 단계(툴팁 "서류합격 · 1차합격 · 2차합격") │ 서류 통과·서류 탈락. 숫자만(단위 X), 0은 흐리게, 숫자는 라벨 글자 시작에 맞춤. 지원한 회사 = 진행 중 + 끝난 곳
- 지원한 회사: 미지원 제외 + 지원일 없는 지원취소(지원 안 하고 취소) 제외. 시안의 1·2차 누적 합격은 면접 횟수가 회사마다 달라 뺌
- '지원 상태' 막대(`computePipeline`): 리스트 지원상태 필터 개수와 같고 합계 = 전체, 탈락·지원취소 포함. 숫자는 막대 옆, 전체 대비 %는 오른쪽 끝. 시안의 단계 전환율 문장 X
- 두 번째 줄(지원 상태·마감 임박·놓친 공고)은 모두 흰 카드, 핵심 지표 띠·분포는 선 — 요약 띠 → 주요 내용 카드 → 보조 정보
- 단위: 기준 문구 "개 회사", 큰 숫자·그 안의 개수 "곳", 마감·공고 "건". 마감 임박은 리스트와 같은 D-n·색, 문구 "7일 안 · 진행 중 N건"
- 유형/규모 분포 라벨 뒤바뀜 수정, 숫자는 막대 옆·%는 오른쪽 끝
- 기간 [전체 | 최근 3개월] (`?period=3m`): 기준 날짜 = 지원했으면 지원일, 아니면 담은 날(서울 기준). 지표·막대·분포에 적용, 마감 임박·놓친 공고는 전체에서

**캘린더** (`/calendar`) — 데이터·URL(`?month`·`?date`) 동작 그대로
- 일정 '기타' 점 #6B6F6A / 다크 #A9B1AC로 변경. 이번 달 아닌 날 배경 `--rally-cell-outside`(#F9FAF8 / #161A18)
- 선택한 날 = 필터 칩과 같은 `chip-on-*` 배경·안쪽 테두리, 오늘 = 숫자 숲색 원. 깜빡임(`?date=` 진입)은 호박색 `warn` 안쪽 테두리를 ::after 오버레이로 — 선택 테두리와 안 겹침
- 이번 달 아닌 날 일정도 흐리게(55%) 표시 (이전엔 숨김)
- 범례는 유형 점 5개만 — 시안의 '메모' 아이콘 범례는 모양으로 알 수 있어 뺌
- 날짜 패널: 시안의 상대 날짜("이틀 뒤") X, 메모 아래 "오늘 페이지에도 같이 보여요" X, 일정 섹션 아래 안내 문장 대신 링크 "채용 리스트에서 일정 추가하기 ›"(일정 있든 없든)
- 모바일: 바텀시트 위치·동작은 그대로, 색은 같은 토큰. 칸은 작게(일정은 점 + 회사명 10px)

**루틴 트래커** (`/routines`, 표는 데스크톱만 — 모바일 요일 화면 그대로) — 체크·블록·드래그·`?week=` 동작 그대로
- 새 토큰: 오늘 열 `--rally-today-col`(#F2F5F1 / #1D2320), 블록 태그 `--rally-tag-bg`(#F0F2EF / #232926), 꺼진 체크박스 테두리 `--rally-check-off`(#BFC4BE / #4A534E — 다크 시안 값이 기존 토큰에 없어서 추가)
- 요일 머리 체크 수: 전부 체크한 날만 "✓ 7/7", 일부 "6/7", 아직 안 온 날 체크 0이면 "—". 체크하면 바로 갱신
- 챌린지 추가는 제목 줄 [+ 추가] 하나만 — 시안의 빈 칸 점선 "챌린지 추가하기"는 중복이라 뺌(빈 칸은 비워 둠). 진행 중 0개일 때만 빈 상태 카드에 [+ 챌린지 추가]
- D-day는 색 경고 없이 글자만(ink-soft)
- 지난 챌린지 목록은 폭 ~720px, 상태 · 제목 · 기록 · 휴지통 고정 열(기록이 제목 바로 옆). 기록 숫자는 **끝난 날까지만** 셈(API 수정 — 포기·완료 뒤 체크가 기록에 안 더해짐)
- 시간 칸: hover ↑↓ 대신 누르면 `[−] 입력 [+]`, ±30분은 입력값만 바꾸고 저장은 Enter·blur
- 드래그 중 놓일 자리 2px 선은 생략 — 다른 행이 밀리며 빈자리가 보임. 끌리는 행에 숲색 테두리 + 그림자만
- 챌린지 모달: "루틴을 하나 이상 선택해주세요."는 루틴을 골랐다 다 풀었을 때만(처음 열 때 빨간 글자 X), 설명 "선택한 루틴을 모두 체크한 날이 1일로 쌓여요."
- 회고: "저장됨"은 저장된 회고가 있으면 계속 표시, [되돌리기](고쳤을 때) 추가

**루틴 통계** (`/routines/statistics`) — 조회·집계(`page.tsx`, `lib/streak.ts`) 그대로
- '이번 주 현황' 격자 뺌(트래커 표와 겹침, `WeeklyBlockGrid` 삭제)
- 스트릭은 공용 `StreakBadge`(학습·운동 통계) 대신 제목 아래 한 줄 "지금 N일 연속 · 최고 N일" + ⓘ. ⓘ는 기본 title 툴팁이 늦게 뜨고 클릭으로 안 떠서 hover·포커스에 바로 뜨는 말풍선(문장마다 한 줄)
- 요약 띠 라벨: '체크 수' → '체크', '완료 일수' → '완료한 날'. 평균 달성률 툴팁 "N칸 중 N칸 체크"(주 = 블록 × 7, 월 = 블록 × 그 달 일수 — 아직 안 온 날 포함, 계산 그대로)
- 요일별 평균은 가장 낮은 요일만 글자 굵게(동률이면 모두, 전부 0%면 없음). 막대 색 단계 없앰
- 요즘 꾸준한 루틴은 기존대로 상위 5개
- 11월 루틴 카드: 기존 % 뱃지 뺌, "N일 체크" + 연속. 오늘 칸 링은 라이트 button / 다크 primary

**운동 기록** (`/workouts`) — 세트 batch 저장·빈 파트 자동 삭제·URL 그대로. 모바일은 카드 접기·타이머 플로팅 버튼 유지
- 시안 '제안' 9곳 모두 채택(종목 추가 위치, [오늘]은 다른 날짜일 때만, 파트+컨디션 한 줄, 카드 3열, 세트별 비교 열, 저장 실패 줄, 타이머 완료 띠, ✕ 뒤 헤더 버튼, 0개 부위 탭 누름)
- 정보 줄: 시안 "지난번 10.31 · PR …" 한 줄 → 두 줄 **"최근 기록 11월 1일" / "최고 기록 102.5kg × 12 · 10월 20일"**(라벨 흐리게·값 진하게). 'PR'·'지난번' 대신 '최고 기록'·'최근 기록', 세트 줄 꼬리표도 "최고". 오늘 세운 최고면 "오늘"(지난 날짜면 "이날"), 기록 없으면 "아직 기록이 없어요"
- 세트 표 오른쪽 열 머리 "최근 기록". 비교는 무게·횟수를 따로(늘면 숲색 "+2.5kg", 줄면 흐리게 "−4회", 같으면 생략) — 시안의 "무게가 늘면 무게만"은 횟수가 줄어도 좋아진 것처럼 보여서 바꿈
- "최고" 꼬리표는 오늘 세트 중 가장 높은 **한 세트**가 오늘 이전 최고를 넘었을 때만. 최고 기록은 **보고 있는 날짜 이전까지**로 계산(API — 전체 기간으로 세면 오늘 기록이 곧바로 최고가 돼 새로고침 뒤 꼬리표가 사라짐. 운동 통계의 최고 기록은 전체 기간 그대로)
- 입력칸 폭: 무게 60~96 · 횟수 48~80px로 먼저 늘고 남는 폭을 '최근 기록' 열이(RIR 끈 카드의 가운데 빈칸 방지). 입력 범위를 저장 전에 확인(무게 0~9999.99 · 횟수 0~999 · RIR 0~10)하고 이유를 그 줄에. RIR 머리글에 ⓘ 말풍선("세트를 끝냈을 때 더 할 수 있었던 횟수예요")
- 타겟 부위: 시안 "…하체·복근·기타" 중 **복근은 뺌**(새 부위 값·주간 목표 기본값이 필요한 기능 작업). '다리'는 '하체'로 부름(저장 값 `leg` 그대로), '기타' = 부위 없음
- 파트가 0개인 날도 "파트 1" 표시(실제 파트는 첫 세트·메모 때). 확인 창 [삭제]만 alert 채움(공용 `ConfirmDialog` 토큰화, 다크는 글자 어둡게). 타이머 알림 "휴식 끝"·소리 없음(앱 안 비프음은 유지)

**화면 문구 정리** (2026-11-04, 앱 전체 · 관리자 화면 제외)
- 이름 통일: 블록·시간블록·라벨 → 루틴, 기업 → 회사(기업 통계 → 회사 통계, 기업 유형 → 회사 유형), 포폴 → 포트폴리오, 미체크 → 아직 안 한, '오늘' 학습 기록 문구는 버튼 이름('이해완료'·'복습필요')에 맞춤
- 해요체 통일, 오류에 다음 행동("잠시 후 다시 해보세요"), 서버 오류 원문·"중복일 수 있음" 추측 문구 제거
- 로그인·가입의 개발용 안내(Console / Confirm email) → 받은 메일 링크 안내
- 설정 회사 유형·학습 카테고리: 영문 key 입력칸 없앰 → 화면이 자동 생성(API·DB 그대로)
- 회사 통계 부제는 '최근 3개월'일 때만, 블로그 [RSS 새로고침] → [새 글 가져오기], 운동 그래프 "top set" → "최고 무게"
