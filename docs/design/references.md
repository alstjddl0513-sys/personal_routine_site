### 시안 대비 구현 변경점

적용하면서 시안과 달라진 곳. **새 페이지 시안을 요청할 때 디자인 세션에 이 섹션을 그대로 공유**해서 기준을 맞춘다. 공통 색·컴포넌트·문구 규칙은 디자인 세션 skill `docs/design/skill/rally-design/SKILL.md`(claude.ai에 zip 업로드)에 — 여기엔 페이지별 차이만.

**색**
- 포인트색: 황토 `#C8963E` → 메리골드 `#E9B949` (라이트·다크 공통). 포인트로 아껴 쓰기
- **메리골드 규칙: 로고 깃발 + 챌린지 진행바 + "목표를 다 채운" 막대만.** 목표가 있는 막대는 평소 primary, 100% 채우면 메리골드. 목표가 아닌 비교용 막대(요일별 평균·순위·구성 막대 등)는 100%여도 primary
  - 적용됨: '오늘' 루틴 바(오늘 블록 전부 체크) · '오늘' 운동 바(목표 100%) · 루틴 통계 요약 띠 '완료한 날'(전체 일수)·'평균 달성률'(100%) · 채용 통계 '최종 합격' 조각
  - 예외: 챌린지 진행바는 진행 중에도 항상 메리골드 — 목표를 다 채우면 자동 완료돼 진행 중 목록에서 빠지므로 "다 채움" 조건으론 볼 일이 없고, 챌린지 자체를 알아보는 표시 역할(2026-11-04 확정)
  - 개편 때 적용할 곳: 운동 '부위별 주간 목표'(`MuscleGoalsCard`, 세트 목표 100%). 휴식 타이머 진행 바는 목표가 아니라 대상 아님
- 일반 진행률 바는 숲색 계열(라이트 `#1F3D30` / 다크 `#8FB5A0`), 목표 미달 바 `#7F988A` / 다크 `#5F8873`
- 나머지는 시안 그대로 (숲색 `#1F3D30`, 바탕 `#F6F7F5`, 카드 `#FFFFFF`, 마감 `#A33B20` / 다크 `#E8957A` 등)

**로고**: 원 없이 깃대(`#F4F2EC`) + 메리골드 삼각 깃발

**사이드바 (전 페이지 공통)**
- 메뉴: 오늘 · 캘린더 · 채용 · 루틴 · 운동 · 학습 · 블로그
- 하위 메뉴(접기 가능): 채용(리스트·통계), 루틴(트래커·통계), 운동(기록·통계), 학습(오늘의 학습·복습·통계)
- 메뉴 줄 40px, 하위 메뉴 32px. 넘치면 메뉴 영역만 스크롤(스크롤바 숨김)
- 하단: 왼쪽 `⚙ 설정`(메뉴와 같은 모양), 오른쪽 끝 🌙 테마 · 🔔 알림
- 닉네임 표시 없음. 로그아웃은 설정 페이지에만(이탈 유도 안 함)
- 관리자 계정일 때만 설정 위에 '관리자 페이지' 줄 — 청록 `--rally-admin-side-*`: 평소 배경 #24484A + 1px 테두리 #3B6E6B + 글자 #D2ECEA(일반 메뉴와 구분되는 버튼 모양), hover는 색 그대로 › 가 나타나고 아이콘 2px 이동, 활성 배경 #9FD0CC + 글자 #12302F(다크 값 별도). 관리자 페이지 내부 대표색은 `--rally-admin`(#2E6E6B / #8CC8C2)

**'오늘' 페이지**
- 헤더에 벨·다크모드 버튼 없음 (사이드바로)
- 인사말은 닉네임만 숲색 (다크 `#A9CBB7`)
- 요약 문장: "오늘 마감 N건, 일정 N건이 있고 루틴은 N개 남았어요."
- 학습: '답 보기' 없음 → ‹ › 화살표로 5문제 미리보기 + 채운 버튼 '답 보러 가기'(`/learn?q=`). 기록한 문제는 작게 "이해함으로 기록했어요". 문제 길이가 달라도 섹션 높이 고정
- 채용: "서류 통과율 36% · 결과 나온 N곳 중 M곳" (분모는 결과 나온 곳만)
- 운동: 하단 설명 문구 삭제, 숫자는 "6 / 10세트"
- 블로그 버튼: "전체 보기"
- 오늘의 학습은 흰 카드 (오른쪽 열: 채용 현황·이번 주 운동은 선, 학습만 카드 — 직접 하는 일이라 왼쪽 카드들과 같은 무게)
- 채용 현황: '면접 중' → '면접 단계'(툴팁 "서류합격 · 1차합격 · 2차합격"), 서류 통과율 설명 "2곳 중 2곳 통과"

**채용 리스트** (`/jobs`, 데스크톱만 — 모바일 카드는 그대로)
- 동작·데이터는 그대로: 공고 링크는 [저장] 유지, 제출본은 이력서 1 · 포트폴리오 1 선택(시안의 문서 여러 개 체크 X), 채용 필터는 '채용중' 칩 하나(시안의 '채용 안 함' X)
- 닫기: 입력형 팝오버(마감일·공고 링크·메모)는 [취소][저장], 즉시 저장형(일정·제출본)은 제목 줄 ✕. 추가 모달 ✕ 유지
- 삭제 아이콘은 휴지통(행·일정), 닫기는 ✕
- 라벨: 필터·표 머리글 "채용여부", 즐겨찾기 버튼 "즐겨찾기", 빈 상태 문구에서 '위' 삭제
- 마감일 칸: "D-2 10.26 월 23:59". 진행 중인 회사만 오늘·내일 `alert`, D-2~3 `warn`(호박색 #9A6700 / 다크 #E3B35C) — 끝난 회사(탈락·최종합격·지원취소)는 강조 X. 지난 건 "마감됨", 빈 칸은 "—"(행 hover 때 "+ 추가")
- 마감일 팝오버: 날짜·시간 입력 분리, 시간 비우면 23:59
- 일정 유형 선택은 커스텀 Select(점 아이콘)
- 열 보기 토글 [간단히 | 자세히] (시안 '전체 열' → '자세히'), localStorage `rally.jobs.columns`, 기본 자세히. 새로고침 깜빡임 없게 `app/layout.tsx` 초기화 스크립트가 `<html data-jobs-columns>`를 달고 CSS로 열 선택
- 간단히: 보조 4열 → "공고 · 일정 2 · 문서 2 · 메모"(없으면 "비어 있음") → 누르면 오른쪽 사이드 패널(시안에 없어서 새로 설계). 패널은 팝오버와 같은 Editor 재사용
- 팝오버 버튼 정리(시안과 다름): 닫기는 5종 모두 제목 줄 ✕(입력형 [취소] 제거), 아래 줄은 [지우기] … [되돌리기(고쳤을 때만)][저장]. 지우기는 저장된 값이 있을 때만, 바로 삭제. 공고 링크의 열기·복사는 입력칸 아래 작은 글자 링크(시안의 [비우기]는 [지우기]로)

**기업 통계** (`/jobs/statistics`) — 시안과 숫자 정의가 다름(상태 이력이 없어 추정 없이 셀 수 있는 것만, `lib/jobs-stats.ts` `computeJobsSummary`)
- 지표 위 한 줄: "담아둔 N개 회사 · 채용중 N곳 · 즐겨찾기 N곳"
- 핵심 지표 3열: 지원한 회사 N곳 / 진행 중 N곳(서류 결과 대기 + 면접 단계) / 서류 통과율 %(**서류 결과가 나온 곳 기준**, /today와 같은 계산). 결과 나온 곳 5곳 미만이면 숫자 흐리게 + "표본 적음"
- 큰 숫자 아래 얇은 구성 막대 → 설명(13px 흐리게) → 점선 → 내역. 내역 점 색 = 막대 조각 색(범례). 1열 막대는 끝난 곳 비율(최종 합격 메리골드·탈락·지원취소, 빈 칸 = 진행 중), 2열 서류 결과 대기(st-applied)·면접 단계(st-int1-passed), 3열 서류 통과(primary)·서류 탈락
- 내역(캡션 없음): 최종 합격·탈락·지원취소 │ 서류 결과 대기·면접 단계(툴팁 "서류합격 · 1차합격 · 2차합격") │ 서류 통과·서류 탈락. 숫자만(단위 X), 0은 흐리게, 숫자는 라벨 글자 시작에 맞춤. 지원한 회사 = 진행 중 + 끝난 곳
- 지원한 회사: 미지원 제외 + 지원일 없는 지원취소(지원 안 하고 취소) 제외. 시안의 1·2차 누적 합격은 면접 횟수가 회사마다 달라 뺌
- '지원 상태' 막대(`computePipeline`): 리스트 지원상태 필터 개수와 같고 합계 = 전체, 탈락·지원취소 포함. 숫자는 막대 옆, 전체 대비 %는 오른쪽 끝. 시안의 단계 전환율 문장 X
- 두 번째 줄(지원 상태·마감 임박·놓친 공고)은 모두 흰 카드, 핵심 지표 띠·분포는 선 — 요약 띠 → 주요 내용 카드 → 보조 정보
- 단위: 기준 문구 "개 회사", 큰 숫자·그 안의 개수 "곳", 마감·공고 "건". 마감 임박은 리스트와 같은 D-n·색, 문구 "7일 안 · 진행 중 N건"
- 유형/규모 분포 라벨 뒤바뀜 수정, 숫자는 막대 옆·%는 오른쪽 끝
- 기간 [전체 | 최근 3개월] (`?period=3m`): 기준 날짜 = 지원했으면 지원일, 아니면 담은 날(서울 기준). 지표·막대·분포에 적용, 마감 임박·놓친 공고는 전체에서

**캘린더** (`/calendar`) — 데이터·URL(`?month`·`?date`) 동작 그대로
- 일정 '기타' 점 #6B6F6A / 다크 #A9B1AC로 변경. 이번 달 아닌 날 배경 `--rally-cell-outside`(#F9FAF8 / #161A18)
- 선택한 날 = 필터 칩과 같은 `chip-on-*` 배경·안쪽 테두리, 오늘 = 숫자 숲색 원. 깜빡임(`?date=` 진입)은 호박색 `warn` 안쪽 테두리를 ::after 오버레이로 — 선택 테두리와 안 겹침
- 이번 달 아닌 날 일정도 흐리게(55%) 표시 (이전엔 숨김)
- 범례는 유형 점 5개만 — 시안의 '메모' 아이콘 범례는 모양으로 알 수 있어 뺌

**설정 첫 화면** (`/settings`, 2026-11-12) — 동작은 #194 그대로(백업 · 계정 삭제 · 닉네임 · 비밀번호 · 알림 · 피드백 · 로그아웃)
- **정렬은 시안(왼쪽 정렬)과 다르게 가운데 한 열 720px** — 옆에 다른 내용이 없어서 1440에서 오른쪽 절반이 비어 왼쪽으로 치우쳐 보임(학습 · 복습과 같은 방식)
- 그 밖의 시안 '다른 후보'는 시안대로(차단됨 잠금 줄 "브라우저에서 알림을 다시 열면 켤 수 있어요.") — 다른 후보는 PR 설명에
- 줄 끝 모양으로 동작 구분: › = 다른 화면 · 테두리 버튼 = 창 · 입력칸 · 세그먼트 = 그 자리에서. 공통 `SettingsRow`. **줄 이름은 명사, 버튼은 동사**로 겹치지 않게: "알림" [설정하기] · "피드백" [작성하기](시안 "알림 설정" [알림 설정 열기] · "피드백 보내기" [피드백 쓰기]). 스크린리더 이름은 "알림 설정하기" · "피드백 작성하기"
- 테마 세그먼트는 글자 대신 **해 · 달 아이콘**(aria-label · title "라이트" / "다크", 사용자 요청)
- 알림 창 항목은 시안(4개)과 다르게 **실제 앱 그대로 "알림 전체" + 6개**(아침 요약 · 채용 마감 · 캘린더 일정 · 루틴 저녁 · 운동 건너뜀 · 챌린지 완주 축하 — 시안 요청 프롬프트가 틀렸었음). "루틴 리마인더" · "운동 스킵 리마인더" → "루틴 저녁 알림" · "운동 건너뜀 알림"
- 버전 "Rally vX"는 시안(로그아웃 바로 아래 왼쪽)과 다르게 **맨 아래 가운데** — 로그아웃 버튼 설명처럼 보여서. 로그아웃(왼쪽) · 계정 삭제(오른쪽 끝)를 떨어뜨린 건 시안대로(잘못 누르지 않게)
- 분할 아이콘은 `Repeat`(시안의 목록 + 되감기는 작게 보면 뜻이 안 읽혀서). 알림 창 채용 마감 · 캘린더 일정 설명은 한 줄로 줄이고, 빠진 조건("앱을 연 날 아침에 알려드릴게요")은 목록 아래 한 줄로
- "계정 삭제…"의 "…"(확인 창이 열린다는 데스크톱 관례)는 한국 앱에선 오타처럼 보여서 빼고 "계정 삭제"
- 비밀번호 변경: 창 → 계정 카드 안 그 자리 입력. 두 칸 폭을 맞춤(첫 칸도 [변경] 앞에서 끝남). 모르는 오류도 원문 대신 "비밀번호를 바꾸지 못했어요…"
- 공용 `ui/Switch`(role=switch, Space 토글) · `ui/Segment` · `settings/SettingsDialog` 새로. 권한은 `lib/notif-permission` 한 곳(허용 요청 뒤 모든 항목이 같이 풀림)
- 모바일: 프로필 카드는 그대로(모바일 개편 때), 닉네임 · 비밀번호 입력은 좁은 화면에서 이름 아래 줄로

**설정 목록 관리** (`/settings/*` 6화면, 2026-11-13) — 동작 · 문구는 #196 그대로
- 공통 부품 `settings/lists/ListCard`(ListCard · ListRow · RowAction · StatusBadge · TagChip · AddLine · ExpandPanel · Field · ListError · SaveStatus) + 페이지 래퍼 `settings/SettingsSubPage`. 회사 유형 · 학습 카테고리는 같은 `LabelListManager`
- 확인 창은 시안대로 **제목 = 질문, 본문 = 결과**("'스타트업' 유형을 삭제할까요?" / "이미 이 유형을 …"). 새 `ListConfirmDialog`(SettingsDialog `compact`) — 공용 `ui/ConfirmDialog`는 관리자 · 챌린지도 써서 그대로
- 입력 오류는 목록 위 상자 → **칸 alert 테두리 + 칸 아래 한 줄**. 목록 위 한 줄은 서버 실패(고치기 · 삭제 · 일시중지)만. 블로그 추가 · 저장 실패는 대개 주소 문제라 RSS 칸 아래에

- 운동 종목 · 블로그 펼침 칸은 좁은 화면(md 미만)에서 이름 · 부위를 한 줄씩(시안은 데스크톱 grid만)
- 빈 상태는 서버에서 목록을 받아 그려서 스크린샷으로 확인 못 함(코드로만 — 회사 유형 · 카테고리 · 종목 · 블로그 "아직 … 없어요.", 분할은 기존 빈 화면)

**설정 이력서 · 학습 질문** (`/settings/documents` · `/settings/questions`, 2026-11-13) — 동작 · 문구는 #198 그대로, 목록 부품은 `settings/lists/ListCard` 재사용
- 미리보기 👁 아이콘 → **문서 이름을 누르면 미리보기**(시안). 파일 줄 버튼은 다운로드 · 이름 고치기 · 삭제 3개
- "대표" 뱃지는 시안(테두리)과 다르게 **숲색 채움**(bg-button · 흰 글자, 사용자 요청) — 섹션에서 하나만 골라진 것이라 한눈에. "N곳 제출" · "올리다 멈춤"은 테두리 그대로
- **문서 줄 순서는 최신순 고정**(시안 · 서버는 대표를 맨 위로) — 대표를 바꿀 때마다 줄이 자리를 바꿔 방금 누른 줄 · 키보드 포커스가 튀어서. 서버 정렬은 다른 화면도 써서 그대로, 설정 화면만
- 대표 라디오는 저장 중에도 disabled로 막지 않음 — 막으면 포커스가 빠져 방향키로 이어 고를 수 없음
- 오류: 올리기 오류는 버튼 아래 → 카드 바로 위 한 줄, 링크 · 질문 입력 오류는 칸 아래 한 줄(목록 위는 서버 실패만)
- 문구 "올리다 멈춘 파일" → 시안 "올리다 멈춤" 뱃지 + 보조 "다시 올려주세요". 파일 크기 표기는 시안처럼 붙여서("1.2MB")
- 학습 질문 칩은 학습 화면의 `ChipButton`을 export해서 같이 씀(상태 저장 · URL은 학습 화면만). 질문 0개면 개수 · 칩 숨김(칩별 개수는 넣었다가 뺌 — 필요 없음, 사용자)
- 시안에 없던 동작 추가: 새로 생긴 줄(올리기 · 링크 · 질문 추가) 2.5초 `row-flash` 강조, 링크 ✎는 제목 · 주소 펼침 칸(파일은 줄 안 이름 고치기), 대표를 지우면 확인 창에 "대표는 ‘…’로 바뀌어요."
- [다운로드]는 "제목.pdf"로 저장(전엔 내부 id 이름). 저장소 이름 옵션은 한글을 %ED%…로 깨뜨려서 브라우저가 받아서 이름을 붙임
- 확인 창 조사는 받침으로 자동("…이력서'를'", "…최종본'을'", 대표 바뀜 "로/으로"), 영어 · 숫자로 끝나면 조사 없이(`lib/korean.ts`). 채용 행 삭제 · 루틴 삭제 창의 "을(를)"도 같이 바꿈
