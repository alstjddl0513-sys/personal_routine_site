Q.TCP 3-way handshake 과정을 설명해주세요.

A.

TCP는 데이터를 보내기 전에, 양쪽이 서로 보내고 받을 준비가 됐는지 세 번의 메시지로 확인해요.

  1. SYN — 클라이언트가 연결을 요청하며 자신의 초기 순서 번호(ISN)를 보내요.
  2. SYN + ACK — 서버가 요청을 받았다는 ACK(클라이언트 ISN + 1)와 자신의 ISN을 담은 SYN을 함께 보내요.
  3. ACK — 클라이언트가 서버 ISN + 1로 답하면 양쪽 모두 ESTABLISHED 상태가 돼요.

세 번인 이유는 양방향 모두 "보낼 수 있고 받을 수 있다"를 확인해야 해서예요. 두 번으로 끝나면 서버는 자기가 보낸 SYN이 클라이언트에 도착했는지 알 수 없어요.

초기 순서 번호를 무작위로 정하는 건, 예전 연결에서 늦게 도착한 패킷과 섞이지 않게 하고 순서 번호를 추측하는 공격을 어렵게 하려는 거예요.

연결을 끊을 때는 양쪽이 각자 FIN을 보내고 ACK를 받는 4-way handshake를 써요. 한쪽이 보낼 데이터를 다 보냈어도 다른 쪽은 아직 보낼 게 남아 있을 수 있어서예요.

이어서 물어볼 만한 질문
  • —SYN Flooding 공격은 어떻게 일어나고, 어떻게 막나요?
  • —연결을 끊을 때 TIME_WAIT 상태는 왜 필요한가요?
