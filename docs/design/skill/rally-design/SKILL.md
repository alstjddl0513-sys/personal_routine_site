# Rally 디자인 시스템

Rally는 1인 취준생이 매일 쓰는 개인 트래커(오늘 · 캘린더 · 채용 · 루틴 · 운동 · 학습 · 블로그 · 설정). 차분하고 정돈된 업무 도구 톤 — 장식·일러스트·그라데이션·그림자 남용 없이, 선과 여백으로 정리.

## 결과물 형식

- 페이지마다 `rally-<page>.html`(라이트) + `rally-<page>-dark.html`(다크) 두 파일
- 정적 HTML, **인라인 style만** (외부 CSS·JS·이미지 없음, 아이콘은 인라인 SVG — 선 두께 1.7~2, round cap)
- 데스크톱 기준 폭 1280px(사이드바 216~240px 포함), 1440에서도 깨지지 않게. 본문 최대 폭 ~1240px. 모바일은 따로 요청할 때만
- 왼쪽에 공통 사이드바 포함, 해당 메뉴 활성
- 실제 구현은 개발자가 토큰으로 옮김 — **아래 색 값 밖의 새 색을 만들면 이유를 HTML 주석으로 남길 것**
- 시안에서 확정이 안 된 제안은 점선 테두리 "제안" 꼬리표로 표시

## 글꼴·크기

- IBM Plex Sans KR (본문 전부), Noto Serif KR은 '오늘' 인사말 한 줄에만
- 숫자는 tabular-nums
- 페이지 제목 26px 700 · 카드·페이지 섹션 제목 17px 700 heading색 · 사이드 패널 제목 18px 700, 패널 안 섹션 소제목 15px 700 heading색(옆 개수는 500 ink-muted) · 본문 15px · 표·보조 13~14px · 작은 설명 12~13px ink-muted
- 줄 높이 본문 1.5~1.6, 표 안 1.35

## 레이아웃

- 본문 여백: 위 36px, 좌우 40px, 아래 64px, 최대 폭 ~1240px, 블록 간격 20px
- **주요 내용 = 흰 카드**(1px line 테두리, radius 8px, 그림자 없음). **보조 정보 = 카드 없이 선(divider/rule)으로 구분**. 한 줄 안에서 카드와 선을 섞지 않음
- 표: 바깥 테두리 line + radius 8px, 머리 thead, 행 사이 divider, hover row-hover
- 격자(달력 등): 칸 사이 1px 선은 divider 바탕이 비치는 방식
- 사이드 패널: 폭 320px 흰 카드, 제목 줄(18px + ✕) → divider 구분선 → 섹션별 padding 16px 20px 18px

## 컴포넌트 규칙

- 버튼 높이·클릭 영역 **최소 40px**. radius 6px
  - 채운 버튼(button 배경, 흰 글자 600): 저장·만들기 같은 기본 동작, 한 영역에 하나
  - 테두리 버튼(btn-border, btn-fg): 보조 동작, 이동(‹ › 오늘)
  - 글자 버튼(ink-muted): 지우기·삭제 같은 가벼운 동작
- 닫기는 제목 줄 오른쪽 **✕(40px)**. 삭제는 **휴지통 아이콘**. 둘을 섞지 않음
- 입력 팝오버·사이드 패널 아래 줄: 왼쪽 [지우기/삭제](저장된 값 있을 때만) … 오른쪽 [되돌리기(고쳤을 때만)] [저장]. [취소] 버튼 없음(✕가 대신)
- **모달은 예외**: 새로 만드는 창(회사 추가·챌린지 만들기)은 제목 줄 ✕ + 아래 [취소] [추가하기/만들기]. 아직 저장된 게 없어 [지우기]·[되돌리기]가 의미 없어서
- 메모·회고 입력: 소제목 옆 상태 "저장됨"(ink-faint) / "변경사항 있음"(warn 점+글자). 단축키(⌘/Ctrl+Enter)는 동작만, 화면에 표시 X
- 선택 상태: chip-on 배경 + 안쪽 2px chip-on-border 테두리 + 굵은 글자
- '오늘' 표시: 숫자만 button색 원(26px) + 흰 글자
- 한 칸에 상태가 겹칠 수 있으면 **표시 위치를 나눔**(오늘 = 숫자, 선택 = 배경·테두리, 강조 = 안쪽 테두리 깜빡임)
- 체크박스: primary 채움, 끝난 항목 글자는 ink-faint
- 진행바: track 바탕, 채움 primary(일반) / marigold(챌린지·목표 달성). 높이는 역할별 — 목록 줄 안에 곁들이는 얇은 바 3~4px('오늘' 루틴 3px, 운동 4px), 숫자 아래 구성 막대·단독 진행바 6px
- 빈 상태: 카드 안 가운데 한 줄 문구 + 필요하면 행동 버튼 하나. 일러스트 없음
- 범례·캡션은 색만으로 구분이 안 될 때만. 아이콘 모양으로 알 수 있으면 넣지 않음

## 문구

시안의 글자도 실제 화면 문구로 그대로 쓰일 수 있으니 샘플 텍스트처럼 대충 쓰지 말 것. **기준: 처음 보는 사람이 한 번 읽고 뜻을 알고, 뭘 하면 되는지 아는 문구.** 확신이 없는 문구는 "제안" 꼬리표 + 다른 후보를 HTML 주석으로 남김.

읽기 쉽게
- 한 문장에 한 가지, 짧게. 같은 뜻이면 더 짧은 쪽
- 개발·내부 용어 X(데이터, 항목, 처리, 동기화, 레코드). 화면에 보이는 이름으로
- 같은 것은 앱 전체에서 같은 단어 — 예: 채용 지원상태 이름(미지원·지원·서류합격·1차합격·2차합격·최종합격·탈락·지원취소)은 목록·필터·통계 어디서나 그대로
- 정해진 이름(화면 문구 기준): **루틴**(블록·시간블록·라벨 X) · **회사**(기업 X) · **포트폴리오**(포폴 X) · **아직 안 한 루틴**(미체크 X) · 학습 표시는 버튼 이름 그대로 '이해완료'·'복습필요' · 띄어쓰기 "이번 주"·"사용 중"
- 뜻이 하나로 읽히는 말("지남" X → "마감됨"). 범위가 넓은 말은 툴팁으로 포함 범위("면접 단계" — "서류합격 · 1차합격 · 2차합격")
- 숫자는 단위와 같이, 분모가 문장에 드러나게("결과 나온 5곳 중 3곳 통과")
- 해요체로 통일("~했습니다"·"~입니다" X)

행동이 보이게
- 사용자에게 행동을 권하는 말("다시 학습해보세요", "채용 리스트에서 일정 추가하기 ›")
- 버튼은 누르면 일어나는 일을 동사로: "저장", "만들기", "일정 추가하기". "확인"·"OK"·"제출" X
- 빈 상태 = 무엇이 없는지 + 다음 행동 한 줄
- 되돌릴 수 없는 동작은 확인 문구에 결과("되돌릴 수 없어요")
- 오류 = 무엇이 안 됐는지 + 어떻게 하면 되는지, 사용자 탓 X

빼는 것
- 기능·작동 원리 설명("오래된 순으로 모아봅니다"), "~하려면 ~에서 해주세요" 같은 안내문, 화면만 봐도 아는 사족 캡션. 꼭 필요한 설명은 툴팁으로
- 단위: 기준 문구 "개 회사", 큰 숫자·그 안의 개수 "곳", 마감·일정·공고 "건", 목록 개수 "개", 일수 "일", 세트 "세트"
- 날짜: "11월 5일 (목)", 마감은 "D-2 10.26 월 23:59", 지난 건 "마감됨", 값 없음 "—"
- 지표는 엄격하게: '완료'는 전부 끝난 것만(일부 체크는 완료 아님), 비율 분모는 결과가 나온 것만. 데이터로 셀 수 없는 추정 숫자 X
- 영어 UI 단어 대신 한국어("Delete" X → "삭제")

## 하지 말 것

- 새 포인트 색, 그라데이션, 큰 그림자, 이모지 아이콘
- 메리골드를 로고·챌린지 바·목표를 다 채운 막대 외에 사용
- 청록(관리자 색)을 일반 페이지에 사용
- 상태 이력·추정이 필요한 숫자 (예: "1차 면접 누적 통과") — 현재 상태로 셀 수 있는 것만
- 드롭세트·템포 같은 운동 세트 심화 옵션 (검토 후 뺀 기능)
